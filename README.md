# Keelkit

Набор Go-модулей, спецификаций и скиллов Claude Code для быстрого создания сайтов: блогов, новостных сайтов,
каталогов, сайтов-визиток.

Каждый сайт — самостоятельное Go-приложение в своём репозитории: один статический бинарник, SQLite, админка,
серверный HTML (templ + htmx). Общее и рискованное — обработка изображений, файлы, вход и сессии, очистка Markdown —
подключается модулями Keelkit как обычные версионируемые зависимости. Поэтому сайт, созданный давно, получает
исправления через обновление зависимости, а не правкой своего кода.

> Проект в разработке (первый этап, модули `v0.x`). Ход работ — [`PLAN.md`](PLAN.md).

## Из чего состоит

| Каталог | Что это |
|---|---|
| [`modules/`](modules/) | модули: `images` (загрузка и обработка изображений), `files` (PDF, видео, SVG), `richtext` (Markdown → безопасный HTML), `auth` (пользователи, сессии, CSRF) |
| [`spec/`](spec/) | спецификация сайта `site.yaml`: JSON Schema и валидатор; [примеры](spec/examples/) |
| [`reference/`](reference/) | эталонный сайт — образец устройства любого сайта: страницы из блоков, блог, админка, SEO, меню, настройки, деплой |
| [`skills/`](skills/) | плагин Claude Code `keelkit`: скиллы для создания и обновления сайтов |

## Что нужно на машине

- **Go** — версия из директивы `toolchain` в `go.mod` (сейчас `go1.27.2`); при `GOTOOLCHAIN=auto` (по умолчанию) Go
  скачает её сам, достаточно любого Go 1.21+.
- **git**.
- **make** (подходит GNU Make 3.81 из macOS).
- **Chrome** — для браузерных тестов админки (`make e2e-browser`).
- **Claude Code** — для скиллов и `make plugin-validate`.

## Создать сайт

1. Подключить маркетплейс и установить плагин (в Claude Code):
   ```
   /plugin marketplace add keelkit/keelkit
   /plugin install keelkit@keelkit
   ```
   Для разработки скиллов — из локального клона: `/plugin marketplace add ~/путь/к/keelkit`.
2. Открыть Claude Code в пустой папке будущего сайта (вне клона монорепо) и запустить `/create-site`
   (или попросить «создай сайт на keelkit»). Готовую спецификацию можно передать сразу:
   `/create-site . ~/specs/site.yaml`.
3. Без готовой спецификации скилл проведёт интервью: по одному вопросу о содержании — что за сайт, какие разделы,
   что в записях, что на главной, нужны ли файлы (есть старый сайт — дайте адрес, разделы предложат по нему).
   Описывать всё заранее не нужно: раздел можно добавить и потом. Скилл составит `site.yaml` и пошаговый план
   `PLAN.md` с чекбоксами и спросит, начинать ли.
4. Дальше — по одному шагу за сессию: очистить контекст (`/clear`), сказать `/create-site` в папке сайта. Скилл
   делает следующий шаг плана (эталон, основа сайта, раздел за разделом, оформление), добавляет тестовое наполнение
   (`make seed`), тесты и коммит, пишет, как проверить шаг, и останавливается. Расход токенов — шаг за шагом,
   план можно менять между шагами.
5. Посмотреть результат:
   ```sh
   make dev        # миграции, dev-данные, сайт на http://localhost:9090
   ```
   Админка — `http://localhost:9090/admin`, dev-вход `admin@example.com` / `adminadmin`.
   Список команд сайта — `make help`, конвенции и развёртывание — `AGENTS.md` сайта.

`create-site` копирует эталон с тега своей версии (`skills/vX.Y.Z`), поэтому скилл и эталон всегда согласованы.
До первого релиза плагина тега нет — эталон берётся из локального клона: `KEELKIT_REPO=~/путь/к/keelkit claude`.

### Пример

Пробный прогон на [`spec/examples/blog.yaml`](spec/examples/blog.yaml) (2026-10-14; тогда `create-site` собирал сайт за
один вызов, теперь — по шагам плана, результат тот же):

```sh
mkdir ~/sites/my-blog && cd ~/sites/my-blog && KEELKIT_REPO=~/keelkit claude
> /create-site . ~/keelkit/spec/examples/blog.yaml
```

- **Вопросы.** Ни одного: `site.yaml` готов. План скилла — одним сообщением: разделы и адреса, разделы админки и что
  добавлено умолчаниями — настройки сайта и меню `[main, footer]` (в `blog.yaml` их нет).
- **Сайт.** Главная и страницы `/{slug}` (Markdown, правки сразу на сайте), блог `/blog` с постами
  `/blog/{slug}` (черновик, дата публикации, обложка со своей картинкой для телефона, категория, живой предпросмотр)
  и лентами категорий `/blog/category/{slug}`, `sitemap.xml`, `rss.xml`, `robots.txt`. Админка: страницы, посты,
  категории, медиатека, настройки, меню. Seed — блог о путешествиях (13 постов, черновик, пост с датой в будущем).
- **Код.** Эталон, приведённый к спецификации: пакеты `internal/content/{pages,posts,categories}`, миграции сайта
  `00001_site_settings` … `00005_posts`, без `people`, модуля `files` и блоков `file`/`people`; `AGENTS.md` сайта
  описывает этот сайт и эталон, из которого он создан.
- **Проверки.** `make lint test e2e-browser spec-validate generate-check`, `check-site.sh`; `make dev` — `/healthz`
  без непримененных миграций, страницы, sitemap, RSS и вход в админку отвечают.

## Обновить сайт

В каталоге сайта: `/upgrade-site` или «обнови сайт» (`/upgrade-site . images` — только один модуль). Скилл поднимает версии модулей и `spec`,
выполняет шаги из их `UPGRADE.md`, переносит исправления эталона с того коммита, из которого создан сайт, проверяет
тесты и миграции на копии БД и оставляет всё в отдельной ветке; что сделать на сервере — в его итоге.
Вручную — по разделам нужных версий в `modules/<имя>/UPGRADE.md`, затем `make test` и `make e2e-browser` сайта.

## Разработка монорепо

Все команды — через `make`, список — `make help`.

```sh
make dev                          # эталонный сайт на http://localhost:9090
make test MODULE=images           # тесты одного модуля (MODULE=spec, MODULE=reference — каталоги)
make check                        # все проверки перед коммитом в main (нужен Chrome)
make spec-validate FILE=spec/examples/blog.yaml
make release MODULE=images VERSION=v0.2.0 DRY_RUN=1   # проверки релиза без тега
make evals SKILL=upgrade-site      # эвал скилла: агент + проверки (вызовы LLM, долго; skills/evals/README.md)
```

CI на GitHub пока запускается только вручную; проверки — локально `make check`, его же вызывает `make release`.

Правила проекта — архитектура, версионирование, миграции, зависимости, конвенции сайтов — в [`AGENTS.md`](AGENTS.md)
(его читают и люди, и агенты). Устройство эталонного сайта — [`reference/AGENTS.md`](reference/AGENTS.md).
