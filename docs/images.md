# Модуль изображений

Часть корневого `AGENTS.md`: читается, когда задача касается этой темы.

## Модуль изображений (первый)

- Загрузка, валидация, обработка (размеры, форматы), хранение.
- Хранилище за интерфейсом `Storage`: пока локальный диск; S3-совместимое отложено до появления потребности.
- У каждого файла хранится **версия профиля обработки**.
- Повторная обработка — штатная идемпотентная команда модуля («переобработать всё с версией профиля ниже N»), безопасная для прерывания и повторного запуска.
- Новые форматы и правила применяются к новым загрузкам автоматически, к старым — только через повторную обработку.
- `Service` (`NewService(db, storage, Config)`): `Upload`, `Get`, `List`, `Delete`, `Reprocess`, `Handler`.
  Метаданные — в таблицах `images_*` базы сайта (SQLite), запросы — `database/sql` без sqlc; сайт к этим таблицам
  обращается только через `Service`, а ссылается на изображение внешним ключом на `images_files(id)`.
- id изображения — 128 случайных бит (base32, 26 символов): адреса не перебираются по порядку.
- Раскладка в хранилище: оригинал `<id>/original.<ext>`, варианты `<id>/v<профиль>/<ширина>.<webp|jpg>`.
  Версия профиля в пути меняет адрес при повторной обработке, поэтому `Handler` отдаёт варианты с
  `Cache-Control: public, max-age=31536000, immutable`. Оригинал (EXIF с GPS) `Handler` не отдаёт никогда.
- Одновременных обработок не больше `Config.MaxConcurrent` (по умолчанию 2: фото 40 Мп — ~400 МБ памяти); остальные ждут.
- `Reprocess(ctx, below)` поднимает изображения с версией ниже `below` до `ProfileVersion`; `below` выше текущей
  версии равносилен ей, поэтому повторный запуск ничего не делает. Файлы, на которые больше нет ссылок, сначала
  записываются в `images_trash` в той же транзакции, что и изменение строк, и удаляются после неё — прерывание в
  любой момент не теряет и не оставляет файлов (остатки убирает следующий `Delete` или `Reprocess`).
- Тесты модуля используют `modernc.org/sqlite` и goose (те же версии, что у сайтов); в код сайта они не попадают.
- Без CGO: ресайз — `golang.org/x/image/draw`, декодирование WebP — `golang.org/x/image/webp`,
  кодирование WebP — `gen2brain/webp` (libwebp, транслированная из WASM в чистый Go).

**Профиль обработки v2** (с `images v0.3.0`; v1 — то же без заглушки)
- Оригинал хранится всегда и побайтно, с EXIF и GPS (без него повторная обработка невозможна) — поэтому публично не отдаётся.
- Ширины 480 / 960 / 1600 / 2400 px, без увеличения; оригинал меньше 2400 px получает ещё вариант своей ширины.
- Выход: WebP q=80 и JPEG q=82 как фолбэк. AVIF — позже, новой версией профиля.
- EXIF удаляется; ориентация применяется до удаления.
- Лимиты: 20 МБ на файл, 40 мегапикселей (защита от decompression bomb).
- Вход: JPEG, PNG, WebP (без анимации). HEIC не поддерживается (нет декодера без CGO).
- Прозрачность: WebP сохраняет альфа-канал, JPEG — на белом фоне. ICC-профили не переносятся (варианты считаются sRGB).
- Заглушка на время загрузки (`Image.Placeholder`): WebP ~32 px по длинной стороне в data URI, колонка
  `images_files.placeholder`; у изображений с прозрачностью её нет (осталась бы видна под прозрачными местами).
  Сайт выводит её размытым фоном под `<img>` (SVG с `feGaussianBlur`, без JS) — в эталоне `web.Picture`.
