# Скиллы

Часть корневого `AGENTS.md`: читается, когда задача касается этой темы.

## Скиллы

Скиллы — тоже софт: версионируются, имеют эвалы в `skills/evals/`, обновляются вместе с модулями.

Распространяются как плагин Claude Code: монорепо — маркетплейс плагинов (`.claude-plugin/marketplace.json`),
плагин `keelkit` — каталог `skills/` (`skills/.claude-plugin/plugin.json`, скилл — `skills/<имя>/SKILL.md`).
Корень плагина — `skills/`, а не корень монорепо: при установке копируются только скиллы и эвалы.
Версия плагина (semver) — только в `plugin.json`, в записи маркетплейса её нет: один источник правды.
Установка: `/plugin marketplace add keelkit/keelkit` (или локальный путь к монорепо), затем `/plugin install keelkit@keelkit`.
Манифесты проверяет `make plugin-validate` (`claude plugin validate --strict`; входит в `make check` без `MODULE`).
Релиз плагина — `make release MODULE=skills VERSION=vX.Y.Z`: тег `skills/vX.Y.Z`, версия в `plugin.json` должна
совпадать, запись в `skills/CHANGELOG.md`, проверки — `make check` целиком. Тег фиксирует и эталон: `create-site`
копирует `reference/` именно с тега своей версии (`skills/create-site/scripts/fetch-reference.sh`; `KEELKIT_REPO` —
локальный клон для разработки и эвалов), поэтому скилл и эталон, по которому он написан, всегда совпадают.
Сайт указывает в своём `AGENTS.md` минимальную версию плагина и эталон (тег и коммит), из которого создан. Скиллы не копируются в репозитории сайтов: скилл обновления должен быть свежее сайта.

Эвалы — `make evals SKILL=<скилл> [CASE=<кейс>]` (`skills/evals/`, устройство — его `README.md`): агент (`claude -p`
с плагином из рабочего дерева) выполняет скилл в каталоге вне монорепо, затем раннер сам запускает проверки — коды
возврата `make`, файлы, git; оценки LLM в проверках нет. Эвалы — по желанию и только с согласия человека
(решение человека, 2026-10-18): прогон — создание целых сайтов, он расходует лимиты подписки человека; запускаются
локально из его Claude Code, одним кейсом и дешёвой моделью, обычно после крупной переделки скилла; в CI их нет.
Главная проверка скилла — его настоящее использование на сайте.

Планируемые скиллы:
- **create-site** — интервью → `site.yaml` и пошаговый план `PLAN.md` сайта (чекбоксы, «Как проверить» с seed у
  каждого шага); затем по одному шагу за сессию по образцу `reference/`, без фоновых агентов.
- **add-section** — добавляет тип контента: правка спецификации → миграция в `db/migrations/` → код в `internal/content/<type>/` → тесты.
- **upgrade-site** — поднимает версии модулей и `spec`, применяет `UPGRADE.md`, переносит исправления эталона с коммита,
  из которого создан сайт (строка в `AGENTS.md` сайта), проверяет тесты и миграции на копии данных, готовит ветку или PR.
- **reprocess-images** — решает, нужна ли повторная обработка, и запускает её.
- **check-drift** (позже) — ищет расхождения между спецификацией и кодом.

Эвал скилла: результат собирается, проходит тесты сайта (включая браузерные) и проверку конвенций
(`create-site/scripts/check-site.sh`). Вход `create-site` — `spec/examples/*.yaml`; вход `upgrade-site` — сайт на
старой версии модуля (эталон с прошлого коммита), плюс `migrate-check.sh` от исходного коммита.
