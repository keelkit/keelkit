# Принятые решения

Часть корневого `AGENTS.md`: читается, когда задача касается этой темы.

## Принятые решения

Решения ниже приняты человеком; не пересматривать без него.

| Вопрос | Решение | Почему |
|---|---|---|
| Путь модулей | `github.com/keelkit/keelkit`, без vanity-домена (с 2026-10-14; раньше — `github.com/voffkin/keelkit`) | путь совпадает с адресом репозитория; домена нет. Хост сменён до первого сайта — позже путь окажется в импортах всех сайтов |
| Видимость | публичный репозиторий в организации `keelkit` (решение человека, 2026-10-14; раньше — приватный под аккаунтом `voffkin`, модули через `GOPRIVATE` и SSH) | сайт создаёт человек без доступа к чужому репозиторию и ключей: барьер входа — только Go и Claude Code |
| Лицензия | MIT | разрешает использовать модули в любых сайтах, в том числе коммерческих и закрытых |
| СУБД | SQLite (`modernc.org/sqlite`, без CGO) | один статический бинарник; хватает для целевых сайтов |
| Доступ к данным | sqlc | ошибки типов ловятся на генерации, а не в проде |
| Миграции | goose, таблица версий на модуль | свой мигратор привёл бы к дублированию или core-модулю |
| Шаблоны и фронт | templ + htmx + чистый CSS | ошибки шаблонов ловит компилятор; без Node |
| Изображения | x/image + `gen2brain/webp` (v0.6+: libwebp, транслированная в Go; раньше — WASM через wazero) | без CGO; профиль версионируется, можно сменить |
| Сборка с тегом `nodynamic` | сайты и монорепо собираются и тестируются с `-tags nodynamic` (`GOFLAGS` в `Makefile`): `gen2brain/webp` не подгружает системную libwebp | результат обработки одинаков на всех машинах и совпадает с тестами; бинарник не зависит от библиотек хоста. Цена — системная libwebp была бы быстрее |
| Картинки в контенте | только блоками (этап 8.5) с id изображения; синтаксиса картинок в Markdown нет, адреса вариантов в контенте не хранятся | адреса меняются при повторной обработке; внешний ключ на `images_files` защищает используемое изображение |
| Ориентация EXIF | свой минимальный парсер в `modules/images/internal/exif`: тег Orientation из JPEG (APP1), PNG (eXIf), WebP (EXIF) | ~150 строк без зависимостей; `rwcarlsen/goexif` без тегов semver, `dsoprea/go-exif` тяжёл ради одного тега |
| Авторизация | модуль `auth` (с этапа 10.4; до него — в коде эталона), одна таблица пользователей; страница входа и оболочка админки — код сайта | вход, сессии и CSRF одинаковы везде и связаны с безопасностью: исправления должны доезжать через `go get` (решение человека, 2026-10-13; раньше — «после второго сайта») |
| `richtext` | модуль `richtext` (с этапа 10.4; до него — `reference/internal/richtext`) | санитайзер — граница безопасности; исправления — через `go get` (решение человека, 2026-10-13) |
| Версии модулей | `v0.x` до второго сайта, затем `v1` | API подтверждается двумя сайтами |
| Скиллы | плагин Claude Code из монорепо | скилл обновления свежее обновляемого сайта |
| Валидатор спецификации | отдельный модуль `spec/` (`github.com/keelkit/keelkit/spec`): схема + `cmd/spec-validate` | сайты и `create-site` вызывают его через `go run …@vX`; зависимости валидатора не попадают в сайты |
| YAML и JSON Schema | `go.yaml.in/yaml/v3`, `santhosh-tekuri/jsonschema/v6` | `gopkg.in/yaml.v3` в архиве; преемник — `go.yaml.in/yaml/v3` |
| Санитайзер HTML для `richtext` | `microcosm-cc/bluemonday` (v1.0.27), политика UGC | стандарт де-факто, не в архиве, BSD-3; релизы редкие — goldmark и так вырезает сырой HTML, санитайзер — второй рубеж |
| Файлы (этап 10.5) | модуль `modules/files` (решение человека, 2026-10-13): PDF, MP4/WebM, SVG; лимит в `Config` (50 МБ); SVG без очистки, с CSP `sandbox` и `nosniff`; замена без смены адреса | хранилище и граница безопасности одинаковы на любом сайте (принцип 6); очистка SVG — сложный и хрупкий код, песочница браузера надёжнее |
| Хеширование паролей | argon2id из `golang.org/x/crypto/argon2` (v0.57.0); m=64 МиБ, t=3, p=4, соль 16 байт, ключ 32 байта; формат PHC `$argon2id$v=19$m=…,t=…,p=…$соль$хеш` | рекомендация OWASP и RFC 9106; нет лимита bcrypt в 72 байта; параметры хранятся в хеше — их можно усилить без миграции, перехешируя при входе |
| Ввод пароля в CLI | `golang.org/x/term` (v0.46.0), `term.ReadPassword` в `site user create` | без эха в терминале на всех ОС; модуль уже в графе через `golang.org/x/crypto`, зависит только от `x/sys` |
| Транслитерация для slug | своя таблица в `internal/slug` (кириллица → упрощённая латиница: ж→zh, х→kh, ц→ts, щ→shch, ю→yu, я→ya, ъ/ь опускаются) | ~40 строк без внешних зависимостей; другие алфавиты — по мере надобности |
| Где миграции типов контента | все миграции сайта — в `db/migrations/`; в `internal/content/<type>/` — запросы, хендлеры, templ | у goose одна последовательность версий на таблицу версий; sqlc читает схему из одного каталога |
| Страницы из блоков (этап 8.5) | тип поля `blocks` в спецификации: только имена блоков (`allow: [text, image, …]`), поля блоков — в коде `internal/blocks/`; посты — тоже блоки | набор блоков — дизайн сайта (принцип 2); один способ вставки картинок для страниц и постов |
| Хранение блоков | JSON-массив в колонке (`json_valid`) + таблица ссылок на картинки (`page_images` → `images_files(id)`), перезаписывается в той же транзакции | порядок сохраняется атомарно, черновик копируется одной колонкой; внешний ключ защищает используемые картинки |
| Модель черновика | отдельная копия: `<type>_contents(kind IN ('draft','published'))`; «Сохранить» пишет черновик, «Опубликовать» копирует его, «Снять с публикации» удаляет опубликованную копию; slug — часть версии | правки опубликованной страницы не видны до публикации; заменяет флажок `draft` |
| JavaScript в админке | админка рассчитана на JavaScript (htmx и свой JS без сборки), запасного варианта без скрипта нет; публичный сайт — без обязательного JavaScript (решение человека, 2026-10-14; раньше — «без JavaScript всё работает» и в админке) | админка — рабочий инструмент редактора в современном браузере; запасной вариант удваивал работу и толкал к неудобным решениям. Сайт смотрят посетители и поисковики — там правило остаётся |
| CI до этапа 14 | GitHub Actions только вручную (`workflow_dispatch`); проверки — локально `make check`, его вызывает `make release` вместо проверки зелёного CI | проверки быстрее и не зависят от GitHub; полный CI — этап 14 |
