# Модуль файлов

Часть корневого `AGENTS.md`: читается, когда задача касается этой темы.

## Модуль файлов (`modules/files`)

- Файлы, которые хранятся как есть, без вариантов: PDF, видео MP4 и WebM, SVG. Формат — по содержимому (сигнатура,
  у MP4 — бренд `ftyp`, у SVG — корневой элемент XML), а не по имени и не по `Content-Type` загрузки.
- Лимит — `Config.MaxBytes`, по умолчанию 50 МБ (сканы PDF бывают под 20 МБ); сайт с видео поднимает его.
  Загрузка идёт потоком в хранилище, превышение обрывает запись (`ErrTooLarge`), ничего не остаётся.
- Адрес — `<id>/<имя>.<ext>` (`File.Path`): имя составляется из исходного при загрузке и не меняется;
  `Replace` (только тем же форматом — `ErrFormatMismatch`) пишет новый ключ хранилища и переключает строку
  в транзакции, старый файл — через `files_trash`, как у `images`. Поэтому кэш — `public, no-cache` с `ETag` версии,
  а не `immutable`. Другое имя при верном id — 404: у файла один адрес.
- `Handler` — `http.ServeContent`: Range и If-Range (видео перематывается), If-None-Match; всегда `nosniff`.
  SVG не очищается, а отдаётся с `Content-Security-Policy: sandbox; default-src 'none'; …`: скрипты в файле не
  выполняются и по прямому адресу; в `<img>` браузер их не выполняет и так. PDF — без CSP: `sandbox` ломает
  встроенный просмотрщик PDF.
- Ссылка из контента — внешним ключом на `files_files(id)` без `ON DELETE`: используемый файл не удаляется.
- Тесты модуля — `modernc.org/sqlite` и goose, как у `images`; `testkit.Run` — контракт для сайтов.
