# Changelog — spec

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — semver (теги `spec/vX.Y.Z`).

## [0.8.0] — 2026-10-14

### Changed
- Путь модуля — `github.com/keelkit/keelkit/spec` (был `github.com/voffkin/keelkit/spec`): репозиторий переехал и стал
  публичным; `$id` схемы — `https://raw.githubusercontent.com/keelkit/keelkit/main/spec/schema.json`. Правила схемы —
  как в 0.7.0. Что сделать сайту — UPGRADE.md, раздел v0.8.0.

## [0.7.0] — 2026-10-14

### Added
- Признак `mobile: true` у поля `image` — у картинки может быть своя замена для узкого экрана (другой кадр той же
  сцены); не задана — на телефоне та же картинка. Только у полей типа записи и настроек, не у полей элемента `list`;
  у других типов полей — ошибка. Изменение добавочное: прежние `site.yaml` остаются валидными.

## [0.6.0] — 2026-10-13

### Added
- Модуль `files` в `modules` (PDF, видео, SVG; `modules/files`). Изменение добавочное: прежние `site.yaml` остаются
  валидными.

## [0.5.0] — 2026-10-13

### Added
- Feature `order` — ручной порядок записей типа: кнопки ↑ ↓ в списке админки, на сайте записи идут в том же порядке
  (люди, проекты, партнёры). Служебная колонка — `sort_order`.

### Changed
- Имя поля `sort_order` стало служебным: его добавляет feature `order`. Спецификация с таким полем перестаёт проходить
  проверку — см. `UPGRADE.md`. Остальные прежние `site.yaml` остаются валидными.

## [0.4.0] — 2026-10-13

### Added
- Модули `richtext` и `auth` в `modules` (рядом с `images`). В `modules` перечисляются все модули Keelkit из `go.mod`
  сайта, в том числе без таблиц (`richtext`); порядок — порядок применения миграций модулей.
  Изменение добавочное: прежние `site.yaml` остаются валидными.

## [0.3.0] — 2026-10-12

### Added
- `settings: { fields: {…} }` — настройки сайта: одна запись, поля как у типа контента, кроме `slug` и `blocks`;
  служебные имена — `id`, `updated_at`.
- `menus: [main, footer]` — меню, которые редактируют в админке (имена без повторов; устройство пунктов — код сайта).
- Тип поля `list` с параметром `fields` — список элементов в поле записи, поля элемента описывает спецификация:
  типы `string, text, richtext, int, bool, date, image, ref`, без `slug`, `blocks` и вложенных `list`; имя `id`
  служебное. `fields` обязателен у `list` и запрещён у остальных типов.
- Feature `seo` — SEO записи вручную (заголовок, описание, картинка для соцсетей); только у типа с полем `slug`.
- Пример `examples/company.yaml` со всеми новыми возможностями.

### Changed
- Имена полей `seo_title`, `seo_description`, `seo_image` стали служебными: их добавляет feature `seo`.
  Спецификация, где они описаны полями, перестаёт проходить проверку — см. `UPGRADE.md`.
  Остальные прежние `site.yaml` остаются валидными (`spec_version` по-прежнему `1`).

## [0.2.0] — 2026-10-09

### Added
- Тип поля `blocks` и его параметр `allow` — список имён блоков (`^[a-z][a-z0-9_]*$`, непустой, без повторов),
  например `body: { type: blocks, allow: [text, image, image_text, quote] }`. Поля блоков в спецификации не описываются:
  набор блоков — дизайн сайта, живёт в коде сайта. `allow` обязателен у `blocks` и запрещён у остальных типов.
  Изменение добавочное: прежние `site.yaml` остаются валидными.

### Fixed
- Ошибка в имени типа контента или поля (`propertyNames`) иногда указывала на чужой путь (например, `/site/BlogPosts`
  вместо `/content/BlogPosts`): `jsonschema` v6.0.3 не копирует путь ошибки, и проверка соседних свойств его затирала.
  Путь теперь сверяется с документом.

## [0.1.0] — 2026-10-02

Первый выпуск.

### Added
- `schema.json` — JSON Schema спецификации сайта, `spec_version: 1`: `site` (name, ровно один язык),
  `modules` (`images`), `content` с типами полей `string, text, richtext, int, bool, date, image, ref, slug`
  и features `draft, publish_date, rss, sitemap`.
- `spec.Validate` и команда `spec-validate`: проверка по схеме и смысловые правила
  (ref на существующий тип, `to` только у ref, не больше одного slug, служебные имена полей запрещены).
  Ошибки — с путём JSON Pointer и строкой/столбцом в YAML.
